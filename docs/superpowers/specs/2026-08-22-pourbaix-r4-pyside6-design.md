# Pourbaix Studio R4 PySide6 Design

Date: 2026-08-22

## Objective

Create the long-term-maintained successor to Pourbaix GUI R3. Preserve every
user-facing R2.8 scientific workflow while replacing the PyQt5 long-form UI
with a PySide6/Qt6 desktop workbench. The migration must retain the established
pymatgen thermodynamic model and release a portable Windows application.

## Confirmed decisions

- Primary users are materials researchers who require publication-ready
  pH-potential stability diagrams without maintaining a Python environment.
- Target platform is Windows x64. The UI stack is PySide6/Qt6.
- R4 is a migration, not a new thermodynamic implementation. The retained R2.8
  source is a UI and workflow reference; the pinned pymatgen environment remains
  the scientific authority.
- The application constructs standard equilibrium Pourbaix diagrams only.
  Metastable analysis is explicitly out of scope for R4.
- H and O are open species in the Pourbaix formalism. They can occur in the
  requested chemical system but are never composition-ratio fields and are
  never keys in `PourbaixDiagram.comp_dict`.
- Aqueous alloy diagrams such as Fe-Ni are valid without the user selecting O.
  Oxides, hydroxides, and aqueous ions can still occur in the resulting diagram.
- The user can define any number of interest-region fills. A fill target must be
  a stable domain exposed by the computed equilibrium diagram; it may be a
  solid, ion, or multi-entry domain. The UI names these items "Interest regions"
  rather than "stable phases".
- The interface supports immediate Chinese and English switching. Chemical
  formulae, element symbols, units, and species labels are not translated.
- Exported data headers remain fixed English for script compatibility.
- The user supplies a Materials Project API key. The R2.8 direct "Get API Key"
  browser link remains available.

## Scientific and data contract

| Field | Meaning | Unit and rule |
|---|---|---|
| Elements | Materials Project chemical system | Valid unique symbols; at least one non-H/O element. |
| Ratios | Relative amounts of closed elements | Dimensionless, finite, positive; one entry for each selected non-H/O element. |
| `comp_dict` | Composition passed to pymatgen | Mapping of non-H/O element symbols only. |
| pH range | Diagram horizontal bounds | Dimensionless finite lower and upper values; lower is strictly less than upper. |
| Potential range | Diagram vertical bounds | Finite V versus SHE lower and upper values; lower is strictly less than upper. |
| Boundary coordinates | Visible domain vertices | pH and V versus SHE generated by pinned pymatgen and clipped only to the requested window. |

R4 introduces no energy model, interpolation, extrapolation, or independent
ratio normalization. Pymatgen remains responsible for Pourbaix construction and
its established ratio handling. Shapely remains responsible for clipping the
stable-domain polygon to the requested display/export window.

The following invariants are mandatory:

- Invalid inputs make no network request.
- Appearance, language, and viewport settings do not alter calculated or
  exported boundary coordinates.
- A changed calculation input invalidates dependent results. A failed
  calculation cannot leave an old figure or old metadata exportable as new work.
- A language change preserves currently entered inputs, valid results, selected
  export settings, and cached entries.
- API keys never enter logs, translation files, manifests, archives, screenshots,
  or exported scientific data.

## Architecture

R4 separates concerns so that the Qt migration does not change scientific
behavior.

| Unit | Responsibility | Must not do |
|---|---|---|
| `domain` | Parse chemical formulae, validate elements/ratios/ranges, create closed composition input | Call Qt, open dialogs, style plots. |
| `materials_project` | Resolve API key, retrieve/cache entries, perform targeted sanitation retry | Own UI state or write exports. |
| `calculation` | Build `PourbaixDiagram`, stable-domain labels, vertices, and result snapshot | Read controls or alter visual preferences. |
| `session` | Own immutable current input, current valid result, stale/failed state, and dependency invalidation | Perform plotting or file-dialog operations. |
| `plotting` | Render a result snapshot with display-only settings | Recalculate data or mutate exported boundaries. |
| `export` | Export result snapshot to CSV/XLSX/TXT and figure to PNG/JPEG/TIFF/SVG; verify output | Re-fetch data silently. |
| `credentials` | Resolve transient, Windows Credential Manager, environment, and legacy-file keys | Write secrets to ordinary configuration or logs. |
| `ui` | Bilingual Qt workbench, field validation, progress/error presentation | Encode thermodynamic formulas. |
| `release` | Build, inspect, archive, extract, smoke-test, and write a manifest | Change scientific behavior to reduce package size. |

The main calculation data flow is:

1. The user selects elements or applies a chemical formula, then edits the
   dynamically generated closed-element ratio table and pH/potential bounds.
2. The domain layer validates all inputs before any network call.
3. The Materials Project layer resolves an API key and fetches cached or live
   entries, using the established single targeted sanitation retry only for the
   known malformed ion-reference failure.
4. The calculation layer creates one result snapshot containing the diagram,
   stable domains, labels, and clipped boundary geometry.
5. The session atomically replaces the current valid result only after a
   successful calculation. Plotting, interest regions, and all exports consume
   that same snapshot.
6. A changed upstream input marks the snapshot stale. A failed new calculation
   clears exportability and reports an actionable error.

## User experience

### Workbench layout

- The left dock, "System and conditions", contains chemical-formula quick fill,
  searchable element tags, a periodic-table selector, dynamic ratios, open H/O
  notice, pH range, potential range, and the generate action.
- The center workspace keeps the diagram visible and provides tabs for Diagram,
  Available regions, and Boundary data.
- The right dock contains dynamically added interest-region rows and collapsible
  R2.8 appearance controls.
- The top toolbar exposes API status, API settings, language, export actions,
  and low-frequency tools. Diagnostics and clear-cache actions remain available
  but do not compete with the calculate action.
- Layouts remain usable at 100%, 125%, and 150% Windows display scaling. Dock
  panels may resize, collapse, or stack; no feature is removed at smaller sizes.

### System composition

- Users may select elements through type-ahead tags, a periodic-table dialog,
  or a chemical formula such as `Sb2Se3`, `BiVO4`, or `FeNi`.
- Formula parsing populates selected closed elements and initial ratios. The
  user may subsequently edit ratios as positive relative values such as `2:3`
  or `0.4:0.6`.
- H and O are displayed as an open reservoir, not as ratio inputs. Removing or
  adding a closed element regenerates the ratio table and marks old results stale.

### Interest regions and R2.8 plotting controls

- "Add interest region" creates a row with visible toggle, computed-domain
  selector with type-ahead, color, opacity, and remove action. There is no
  fixed limit of four rows.
- After calculation, selectors list the available stable-domain labels. Invalid
  selections are reported and never silently substituted.
- R2.8 controls remain available: show ion labels; label font, size, optional
  label background, color, and alpha; axis/tick font and sizes; X/Y labels and
  sizes; spine, solid, and stability-line widths; major/minor tick settings;
  hydrogen and oxygen water-line colors; image DPI and transparent background.
- Advanced display settings are categorized and collapsed by default. They are
  display-only and never affect the result snapshot or boundary export.

### Bilingual interface

- A top-level Chinese/English control switches application-owned text without
  restart and persists the selected language using non-secret preferences.
- All app-owned labels, actions, validation errors, diagnostics, dialogs,
  help text, and success messages have Chinese and English translations.
- Scientific plot text retains a stable terminology/font strategy. Default
  `pH` and `E (V vs. SHE)` remain scientifically identical in both languages;
  user-entered axis labels are preserved verbatim.
- The selected language does not invalidate a result or alter cached data.

## API key behavior

- "Get API Key / 获取 API Key" opens the R2.8 direct Materials Project URL in
  the default browser. A second help action opens the maintained official API
  documentation URL.
- The API panel provides masked entry, show/hide, connection test, optional
  remember-on-this-computer, replace, and forget actions.
- Resolution order is: current UI entry, Windows Credential Manager, one of
  `MP_API_KEY`, `MAPI_KEY`, or `PMG_MAPI_KEY`, then legacy `mp_api_key.txt`.
- Detecting a legacy file offers an explicit migration to secure storage. R4
  must not modify or delete that file without user action.
- New remembered keys use Windows Credential Manager for the current Windows
  user. New plaintext key-file writes are forbidden.

| R2.8 capability | R4 requirement |
|---|---|
| Comma-separated elements and ratios | Preserved through richer element/ratio controls; legacy text import remains accepted. |
| API key field and direct browser link | Preserved with masked entry, test action, optional secure remembering, and direct link. |
| pH and potential range | Preserved as validated min/max controls. |
| Font, axes, line, and tick controls | Preserved in categorized Appearance settings. |
| Ion labels and label background fill | Preserved. |
| Four fixed fill species | Replaced by unlimited dynamic interest-region rows. |
| H/O stability-line colors | Preserved. |
| Available species labels and completion | Preserved through Available regions and interest-region selectors. |
| CSV/XLSX/TXT boundary export | Preserved with fixed English headers and snapshot-based export. |
| PNG/JPEG/TIFF/SVG export, DPI, transparency | Preserved. |
| Five-minute entry cache, diagnostics, clear cache | Preserved; diagnostics also report key source without exposing a key. |
| Local logging and full tracebacks | Preserved for logs; user dialogs remain concise and actionable. |

## Error handling and state

- Field errors identify the relevant element, formula, ratio, pH, potential, or
  appearance field. They do not trigger a Materials Project request.
- Missing credentials present a bilingual API-key action rather than a raw
  traceback.
- Network, Materials Project, malformed ion-reference, plotting, export, and
  credential-storage failures are logged locally without secrets. User-facing
  messages explain the recovery action.
- Export writes to a temporary target where feasible, verifies presence and
  non-zero size, then reports the completed path. Boundary export is read back
  structurally during tests.

## Test and acceptance strategy

The R4 test suite is written before production migration changes. R2.8 is a
behavioral reference, not an unqualified numerical oracle. Pinned pymatgen and
independent contract tests remain the authority for scientific construction.

Required test layers:

1. Domain tests: symbols, duplicates, chemical-formula parsing, non-H/O ratio
   count, positive finite values, H/O exclusion, and ordered finite ranges.
2. Materials Project tests: cache hit/expiry, key resolution precedence,
   targeted retry behavior, and no-secret logging.
3. Calculation/session tests: one successful result snapshot, stale invalidation,
   failed-calculation export blocking, and display/locale isolation.
4. Export tests: CSV/XLSX/TXT headers, clipping, non-empty write, and readback;
   figure format, DPI, and transparency behavior.
5. UI tests: English/Chinese switch, state preservation, dynamic interest-region
   add/remove, available-domain selection, R2.8 control presence, and Qt smoke.
6. Release tests: clean build, package inspection, package smoke, archive,
   extraction, extracted smoke, manifest generation, and forbidden-secret scan.

Acceptance requires successful live Materials Project examples when a valid user
key is available: Ti-O with ratio `1`, Sb-Se with ratios `2:3`, and an alloy
without O such as Fe-Ni with ratios `1:1`. The exact returned phases are not
snapshotted as immutable truth because the remote database can evolve; requests
must instead complete, respect the input contract, and produce internally
consistent diagram/export snapshots.

## Scope boundaries

R4 includes the PySide6 migration, workbench redesign, R2.8 parity, dynamic
composition and interest regions, bilingual UI, secure optional key memory,
and reproducible Windows packaging.

R4 excludes custom thermodynamic models, metastable-domain calculations,
offline Materials Project datasets, automatic update infrastructure, installers,
code signing, and automatic deletion of legacy key files. Background fetching
or worker-thread redesign is deferred unless needed to keep the confirmed UI
responsive during real queries.

## Release and external validation

- Build and archive only from a clean, locked Windows x64 environment.
- Produce a new machine-readable release manifest containing dependency/tool
  versions, source revision, test results, smoke exit codes, archive size,
  entries, SHA-256, forbidden-secret scan, and external-acceptance status.
- Verify launch, bilingual switching, plotting, export, API-key controls, and
  resize behavior at 100%, 125%, and 150% display scaling.
- Keep clean-machine, non-administrator, and live-Materials-Project checks as
  Pending until performed on the final archive and recorded against its SHA-256.

## Implementation sequencing after approval

1. Produce a detailed implementation plan from this specification.
2. Establish and lock the PySide6 Windows environment.
3. Add failing domain, session, credential, export, and compatibility tests.
4. Implement the non-UI boundaries and verify scientific invariants.
5. Implement the PySide6 workbench and bilingual resources against tested state.
6. Build, test, package, archive, extract, and validate the R4 release.
